# 产品方向

PARALLAX 第一阶段先做 Web / PWA，不单独做移动端 App。

原因：

- 技术社区内容以阅读、搜索、编辑、引用和外链分享为主，Web 的传播和 SEO 更合适。
- 单台 Linux 主机自托管时，Web 部署和升级成本低，公网穿透、反向代理、证书都能集中处理。
- PWA 可以覆盖大部分移动端阅读和轻互动场景，等社区规模起来后再评估原生 App。
- 开源贡献者更容易在浏览器里调试 Web 产品，贡献门槛更低。

## 前端技术栈

当前不切 Vue，继续使用 Next.js + React + TypeScript。

这个选择不是因为 Vue 不适合，而是因为第一版需要同时处理页面、服务端渲染、登录、上传、数据库读写、健康检查和部署。Next.js 让这些能力在一个模块化单体里闭环，代码量和部署复杂度都更低。

如果未来出现这些情况，可以重新评估 Vue：

- 社区已经有稳定后端 API，前端需要完全独立演进。
- 贡献者主体更熟悉 Vue。
- 需要把前端作为独立主题系统或插件宿主拆出来。

## World Signals

第一版前台不再使用节点连线图。PARALLAX 的流动感来自两种心跳：

- Human Content：社区成员发布的真实内容。
- World Signals：Radar 从外部世界捕捉到的真实变化。

Radar 不作为“AI 助手”出现在前台，也不自动发帖。它是社区背后的信息循环系统：抓取、去重、理解、排序，然后把值得人类接管的 Signal 送回首页和观测台。

第一版能力：

- 内容来自已发布的文章、文档、视频和图文。
- `/map` 页面作为观测台，展示真实 World Signals。
- 首页在存在真实 Signal 或社区新内容时显示 `New`，没有真实条目时不渲染占位区。
- 没有真实内容或信号时不渲染占位模块，不放演示节点、虚构研究成果或 0 计数面板。
- 旧的内容关系模型可以作为后端预留，不作为当前交付界面的主表达。

后续演进：

- 接入 PARALLAX Radar 的真实资料采集任务。
- 支持 GitHub 热门项目、开源模型、AI 圈、游戏圈、光谱科学、宇宙生命和哲学探索资料源。
- 支持 Signal 生命周期：`NEW`、`RISING`、`ACTIVE`、`COOLING`、`ARCHIVED`。
- 支持人类接管 Signal：发起讨论、转为文章、转为项目或工作室任务。
- 如果未来重新需要知识关系，再从数据层恢复关系视图，而不是在第一版强行做图。

## 身份卡

身份卡适合做进系统，而且应该放在账号体系旁边，而不是只作为图片素材展示。

它承担三件事：

- 给创始成员和普通成员一个可展示、可追溯、可扩展的社区身份。
- 为个人主页、成员目录、贡献者徽章和未来插件权限提供稳定入口。
- 支持“先预留身份，后绑定邮箱账号”的社区运营方式。

第一版保留现有短码和卡面资产。初创成员使用月光卡，后续邮箱注册用户自动获得白卡。未来如果要开放邀请制、贡献等级、特殊卡面或链式纪念徽章，都可以继续扩展 `IdentityCard`，不需要重做 `User`。

## 上线口径

下周上线前坚持“零假数据”：

- 首页、探索、观测台和个人页都只读数据库真实记录。
- 种子脚本只创建真实初创成员和站长账号，不创建演示文章、演示评论或虚构统计。
- 没内容就是空状态，由站长和社区成员发布第一批真实内容。
- 邮箱验证上线前必须接入可用 SMTP，并做一次真实收信测试。
